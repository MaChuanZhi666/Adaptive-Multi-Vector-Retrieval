# PLAID / WARP / IGP 统一评测协议

## 目标

在同一数据集、同一 query 集、同一硬件条件下，公平比较 PLAID / WARP / IGP 的：

- 检索质量；
- 查询延迟；
- CPU/GPU 表现；
- 阶段耗时；
- 候选规模；
- 索引构建成本；
- 索引持久化友好程度。

## 数据集口径

先用：

- LoTTE lifestyle/dev；
- 50,000 passages；
- 48 queries；
- TopK=100；
- SEARCH_REPEATS=3。

后续扩展：

- LoTTE 全量；
- 更多 query；
- 多个 split；
- MS MARCO 或 BEIR 子集。

## 设备口径

每个方法尽量测两类：

- GPU：Colab Tesla T4 或实验室 GPU；
- CPU：单线程、多线程都记录。

如果某方法不支持 GPU 或不支持 CPU，要明确标注：

- `device_supported=False`
- `reason=只支持 CPU / 只支持 GPU / 依赖未编译`

## 质量指标

必须统一：

- Success@5
- Success@10
- Success@100
- Recall@10
- Recall@100
- MRR@10

## 速度指标

必须统一：

- latency_mean_ms
- latency_p50_ms
- latency_p95_ms
- qps_sequential

## 阶段耗时

建议统一字段：

- query_encode_ms
- candidate_generation_ms
- prune_ms
- decompress_ms
- maxsim_or_gemm_ms
- score_pids_ms
- sorting_ms
- end_to_end_ms

说明：

- 如果 prune/decompress/MaxSim 拆不开，先填 `score_pids_ms`；
- 拆不开的字段填 NaN；
- 报告里必须说明原因。

## 规模指标

- candidate_count_mean
- final_scored_count_mean
- index_build_time_s
- index_size_gib
- peak_gpu_memory_gib
- peak_cpu_memory_gib

## 输出文件

每个实验最终都输出：

- `summary.csv`
- `per_query_results.csv`
- `index_stats.csv`
- `metadata.json`
- `quality_latency_tradeoff.png`
- `stage_latency.png`
- `conclusion_draft.md`
